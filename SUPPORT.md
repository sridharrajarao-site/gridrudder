# Support

GridRudder is pre-production, lab-stage software. There is no production-support commitment, service-level agreement, certified hardware list, or unattended-operation guarantee.

## Public help

Use GitHub issues for reproducible simulator, read-only probe, audit, documentation, and website problems. Search existing issues first and use the appropriate template. Prefer synthetic reproductions and redact infrastructure and customer identifiers.

Use discussions only if maintainers explicitly enable and moderate them. General design-partner qualification belongs at `pilot@gridrudder.com`, not in a public issue.

## Private reports

Follow [`SECURITY.md`](SECURITY.md) for vulnerabilities or unsafe control behavior. Do not open a public issue or attach credentials, private hardware evidence, customer telemetry, or exploit material.

## Hardware questions

Read [`docs/compatibility.md`](docs/compatibility.md) before reporting hardware behavior. Public compatibility observations must be read-only and sanitized. They do not authorize a GPU write or create a support commitment.

The attended performance-trial boundary requires a separately reviewed integration, exact authorization, a non-production or approved maintenance window, an attending operator, independent timestamped whole-server telemetry, and verified restoration. It has no general-purpose hardware CLI.

## Response expectations

Maintainers will prioritize safety and security reports, but no response or fix time is guaranteed. Support for a future commercial service will be governed by separate written terms and is not included with the Apache-2.0 source.
